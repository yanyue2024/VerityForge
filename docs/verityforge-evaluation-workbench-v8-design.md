# VerityForge 评测工作台改版

## 目标

评测页的首要任务是让管理员在 10 秒内回答三件事：哪条链路更好、质量损失来自哪里、下一步该打开哪一道样例。页面不把创建配置、数据集内容、运行过程和逐题诊断塞进同一层，而是按结果到证据逐级下钻。

## 信息架构

1. **评测总览**：固定展示最近的 v8 终版 Fast/Deep 对照；先看成功率、Recall@5、AEC/RCC、回答语义和成本，再进入任务或样例。
2. **评测任务**：显示状态、模式、通过率、质量摘要、耗时和异常数；进行中的任务优先显示进度。
3. **数据集**：管理 Query 集，不与结果指标混排。数据集详情保留问题、标准答案和预期文档的展开查看。
4. **任务详情**：第一层是结果判读，第二层是问题分类/异常，第三层才是完整运行配置。
5. **样例详情**：链路状态、模式、四项样例指标、答案/标准答案、召回文档和技术诊断。

## 视觉方向

- 继续使用 VerityForge 的白底、墨色文字、品牌蓝和少量证据蓝；失败使用珊瑚色，质量待复核使用琥珀色。
- 评测总览的签名元素是“质量-成本轨道”：每个指标用同一行对齐 Fast/Deep 的数值与短条，避免五个孤立的大卡片。
- 采用 12 列桌面网格、窄标题栏和细分隔线；信息密度提高，但每一层只回答一个问题。
- 运行配置、完整 JSON 和原始技术指标默认收起，避免排挤最重要的结果。

## 结果口径

- 链路成功率：是否得到最终答案；它和质量指标分开。
- Recall@5：预期文档是否进入前五。
- AEC：Accepted Evidence 对标准答案的覆盖；Fast 没有 Accepted Evidence 时显示“—”，不伪造为 0。
- RCC：最终研究上下文对标准答案的覆盖。
- 语义答案/引用支持：可选模型判定，缺少判定显示“—”。
- Token 和延迟：保留总量、平均值和 P95；Fast 未记录 token 时明确标注“未记录”。

## 终版数据

- `Deep Read 三策略 5 案例试跑`：导入 v8 终版完整 Fast/Deep 对照，首页作为主比较。
- `中文企业技术知识库 Agentic Retrieval 困难集 v1`：导入 v8 终版 200 题 Deep 终版结果，作为规模验收。
- 导入脚本可重复运行，遇到相同数据集、任务或样例 ID 时跳过，不覆盖用户已有数据。
