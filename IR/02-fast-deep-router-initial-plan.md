# Fast / Deep 问题路由器初版规划方向

> 文档状态：方案选择
> 依赖：`01-fast-deep-router-requirements.md`

## 1. 候选路线

### 1.1 远程大模型二分类

优点是语言理解面广，缺点是每题新增一次模型调用、Token、网络延迟、JSON 校验和后端失败面。当前仓库的旧 `AgentStructuredReasoner.classify` 即属于此路线。

结论：不作为默认方案。本次目标首先是节省 Deep 成本，不能用新的生成式调用抵消收益。

### 1.2 本地小模型分类

可以使用 BGE 分类头、轻量 Transformer 或传统文本分类器。它比远程 LLM 便宜，但仍需要训练数据治理、模型发布、推理资源、阈值校准和漂移监控。

结论：保留为后续扩展。现有样本的 Fast 边界具有明确结构，第一版没有必要引入新的模型生命周期。

### 1.3 纯规则全部单意图走 Fast

实现最简单，但现有困难 200 题回放结果为：

| 策略 | Fast 题数 | Recall@5 | Token 节省 | 时间节省 |
|---|---:|---:|---:|---:|
| 全部 Deep | 0 | 0.963333 | 0 | 0 |
| 所有单意图 Fast | 60 | 0.883333 | 约 22.03% | 约 21.51% |

结论：拒绝。收益明显，但 Recall 下降 `0.08`，并跌破默认 `0.90` 质量线。

### 1.4 风险优先的确定性级联

先识别强 Deep，再识别高置信 Fast，剩余默认 Deep。该路线不追求标签上的最大 Fast 比例，而追求“Fast 误放率”足够低。

结论：选定。

## 2. 收益曲线与选择

现有 200 题逐题 Fast / Deep 结果给出了几个可验证点：

| 策略 | Fast 题数 | Recall@5 | Token 节省 | 时间节省 | 判断 |
|---|---:|---:|---:|---:|---|
| 全部 Deep | 0 | 0.963333 | 0 | 0 | 质量上界 |
| 仅 Keyword Sparse Fast | 20 | 0.948333 | 约 7.02% | 约 7.08% | 有损且收益较低 |
| 全部 Semantic Paraphrase Fast | 40 | 0.898333 | 约 15.02% | 约 14.43% | 略低于 0.90 |
| 全部单意图 Fast | 60 | 0.883333 | 约 22.03% | 约 21.51% | 质量损失过大 |
| 高置信技术锚点 Fast | 28 | 0.963333 | 约 9.37% | 约 9.26% | 当前最优保守点 |

“高置信技术锚点”策略在这组数据上同时支配“仅 Keyword Sparse Fast”：节省更多且没有 Recall 损失。因此初版不采用题型粗分类，而采用可解释信号。

## 3. 初版决策漏斗

```text
显式 FAST / DEEP？
  -> 是：尊重用户选择
  -> 否：AUTO

AUTO：
  -> 标准化问题
  -> 强 Deep 信号扫描
     -> 命中：DEEP
  -> 高置信 Fast 信号扫描
     -> 单文档/章节直接查找：FAST
     -> 简单资料存在性判断：FAST
     -> 稳定技术标识：FAST
  -> 其余：DEEP
```

## 4. 为什么默认 Deep

路由错误不是对称的：

- 本该 Fast 却走 Deep：主要损失 Token 和时间，答案质量通常不下降；
- 本该 Deep 却走 Fast：可能漏掉 Goal、文档或证据面，直接损失 Recall 和答案完整性。

因此初版优化目标不是总体分类 Accuracy 最大，而是：

```text
在满足 Recall 下限的前提下，最大化可避免的 Deep 研究成本。
```

## 5. 迭代顺序

1. 实现纯函数路由器和稳定 reason code；
2. 接入 `RunCoordinator.selectMode`；
3. 用 AUTO 平衡 200 题检查显式 Fast 识别能力和 Deep 保护能力；
4. 用困难 200 题历史 Fast/Deep 结果做逐题回放；
5. 若 Recall 低于 0.90，收紧 Fast 条件；
6. 若 Recall 无损但节省低于 5%，只扩展有跨域证据支持的高置信 Fast 信号；
7. 不通过针对单个 benchmarkCaseId 的例外名单调参。

## 6. 预留扩展

只有在确定性规则长期出现较大“默认 Deep”灰区、且灰区流量足以抵消模型成本时，才考虑第二级本地分类器。即便增加分类器，也必须保持：

- 强 Deep 规则不可被覆盖；
- 分类器低置信结果 Fail Deep；
- 远程生成式 LLM 不进入同步关键路径；
- 线上阈值通过历史双模式结果校准，而不是只优化人工标签准确率。
